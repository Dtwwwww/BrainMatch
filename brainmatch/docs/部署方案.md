**优势：**

## 三、Supabase 生产环境配置

### 3.1 数据库建表

1. 登录 [Supabase Dashboard](https://supabase.com/dashboard)
2. 选择项目 → SQL Editor
3. **完整运行** [`supabase-schema.sql`](./supabase-schema.sql)

### 3.2 关键检查项

| 检查项 | 说明 |
|--------|------|
| `pgvector` 扩展 | `CREATE EXTENSION IF NOT EXISTS vector;` — 语义缓存需要 |
| RLS 策略 | 所有表的 RLS 已通过脚本启用，确认无误 |
| `handle_new_user()` 触发器 | 新用户注册自动创建 profile + 1 次免费额度 |
| `service_role` key | 仅用于服务端回调，**绝不暴露到前端** |

### 3.3 Auth 配置

1. **Auth Settings → Site URL**：设为你的生产域名（如 `https://brainmatch.example.com`）
2. **Auth Settings → Redirect URLs**：添加回调白名单
   ```
   https://brainmatch.example.com/auth/callback
   https://brainmatch.example.com/api/auth/wechat/callback
   ```
3. **手机验证码**：如果使用 Supabase 内置 SMS，需配置 SMS Provider；否则用自定义 `/api/auth/phone/` 路由

### 3.4 数据库备份

- Supabase Pro 提供自动每日备份（7 天保留）
- 建议额外启用 **Point-in-Time Recovery**（PITR）

## 四、环境变量配置

### 4.1 生产环境变量清单

复制 `.env.example` 并填入真实值：

```bash
# ========== 必填 — Supabase ==========
NEXT_PUBLIC_SUPABASE_URL=https://<your-project>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=sb_publishable_<xxx>
SUPABASE_SERVICE_ROLE_KEY=sb_secret_<xxx>          # ⚠️ 仅服务端，不含 NEXT_PUBLIC 前缀

# ========== 必填 — AI 模型 ==========
AI_PRIMARY_MODEL=deepseek-chat                      # 主力模型
AI_FALLBACK_MODEL=                                  # 降级模型（可选）
DEEPSEEK_API_KEY=sk-<xxx>
OPENAI_API_KEY=sk-<xxx>                             # 如果使用 OpenAI 模型

# ========== 必填 — 应用 ==========
NEXT_PUBLIC_APP_URL=https://brainmatch.example.com  # 生产域名
NODE_ENV=production

# ========== 必填 — 支付 ==========
PAYMENT_PROVIDER=xunhupay                           # mock（开发）| xunhupay（虎皮椒）
XUNHU_APPID=<虎皮椒商户ID>
XUNHU_SECRET=<虎皮椒密钥>
XUNHU_API_BASE=https://api.xunhupay.com             # 默认，不要改末尾斜杠
XUNHU_NOTIFY_URL=https://brainmatch.example.com/api/payment/callback

# ========== 可选 — Redis 限流 ==========
UPSTASH_REDIS_REST_URL=https://<xxx>.upstash.io
UPSTASH_REDIS_REST_TOKEN=<xxx>
# 未配置时自动回退到内存限流（服务重启清空）
```

### 4.2 Vercel 环境变量管理

在 Vercel Project Settings → Environment Variables 中添加：

| 变量 | 环境 | 敏感 |
|------|------|------|
| `NEXT_PUBLIC_SUPABASE_URL` | Production/Preview | ❌ |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Production/Preview | ❌ |
| `SUPABASE_SERVICE_ROLE_KEY` | Production/Preview | ✅ |
| `DEEPSEEK_API_KEY` | Production/Preview | ✅ |
| `OPENAI_API_KEY` | Production/Preview | ✅ |
| `XUNHU_APPID` | Production | ✅ |
| `XUNHU_SECRET` | Production | ✅ |
| 其余所有变量 | Production/Preview | 按需 |

**注意：** `NEXT_PUBLIC_*` 前缀的变量会被打包到浏览器端 JS，不要在其中有 secrets。

## 五、支付系统生产验证

### 5.1 虎皮椒商户注册

1. 前往 [xunhupay.com](https://www.xunhupay.com) 注册个人商户
2. 获取 **微信 APPID** 和 **支付宝 APPID**（两个独立通道）
3. 获取对应的 **Secret**

### 5.2 回调 URL 公网可达性

支付回调 URL 必须是公网可达的：

```
POST https://brainmatch.example.com/api/payment/callback
```

- ✅ Vercel 部署后自动可达
- ⚠️ 本地开发用 mock 模式，真实支付只在生产环境测试

### 5.3 回调验证流程

```
虎皮椒 POST 回调 (form-urlencoded)
  → route.ts 解析 body
  → xunhupay.ts handleCallback 验证签名
  → 检查 status === 'OD'
  → 幂等性检查（已有 paid 则跳过）
  → 更新 orders 表 → 更新 user_credits → 插入流水
  → 返回纯文本 "success"
```

### 5.4 测试支付

1. 设置 `PAYMENT_PROVIDER=xunhupay`（生产环境）
2. 虎皮椒支持 **1 分钱测试**
3. 如果生产前需要预测试：可暂时将 `total_fee: 0.01` 硬编码下单

## 十二、可选：Docker 自托管方案

如果需要非 Serverless 的自托管部署：

```dockerfile
# Dockerfile
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static
COPY --from=builder /app/public ./public
EXPOSE 3000
CMD ["node", "server.js"]
```

并在 `next.config.mjs` 添加：
```js
output: 'standalone',
```
